**Goal:** One durable, fail-closed handover engine shared by crew and Office, with no live activation.
**Spec:** `git show fbdf99e736659a16496f22fcadd9b2bb65050904:docs/superpowers/specs/2026-10-30-automatic-crew-handover-design.md`; Gamma PASS b0cbca124 and Zeta generation-bound routing CAS clarification.

Beta: Office `seat_host.py` / adapter / tool sandbox lifecycle; no duplicate coordinator. Alpha alone authorizes a live swap. Current unverified real crew adapters remain manual.

## Boundaries and edge cases

No funded imports/actions, .env changes or service changes. No hook installation, model launch or retirement in this build. Host-approved adapters supply identity, permissions, safe-point evidence, process attribution and effect lookup; notes never supply executable descriptors. Added funded latency is unmeasured and off-path; no observed zero-latency claim. Per-role durable incarnation CAS survives restarts; OS locks are released before external effects. Unknown task paging, child state, launch/ACK outcome, quota and telemetry remain unknown. UTC deadlines and monotonic waits stay distinct. Two readiness ACKs, exact route generations and message cursors prevent stale takeover; route rollback never restores an old generation. Queued intake continues. Same-UID hostile processes remain outside the isolation guarantee.

Add host-only staged methods; existing manual register behavior remains available except a staged candidate cannot self-register as the active owner. No public automatic registration command until trusted client capabilities pass.

Implement one private fsynced journal and per-role fence; no network/provider code in core. External adapters reconcile each durable effect ID before retry.
3. RED detector/note witnesses: 59.9/60/74.9/75%, latest input not lifetime totals, Claude cache accounting, wrong/stale/zero-window samples and compaction latching/dedup. Atomic session-written note + host task inventory double-read, complete pagination, identity/hash/size/secret checks, sticky web taint and quoted data. Preserve existing brain_cli human handover mode with an additive checkpoint output contract.
4. RED message continuity witnesses: watermark at park, durable intake while held, original-ID replay with old consumption true/false/unknown, no automatic replay of non-idempotent effects, and old reply endpoint continuity. ACK is not send status or task completion.
5. Fault witnesses: kill/restart at intent/effect boundaries; lost activation ACK freezes rather than relaunching; memory-pressure fallback first reaps candidate, seals old checkpoint, proves old harness gone, then launches once; failure restores only exact old checkpoint when proven. Rate/storage/park caps and unavailable page transport remain bounded and visible. A planted owned child defers without wrapper leases; real untrusted/unattributable client adapters stay manual.
6. Focused `pytest -n 2` only during funded deploy; no full suite without shared host lock and Alpha window. Each coherent slice gets an owned-path commit, Zeta source gate and Gamma witness gate. Keep no runtime claim. Retention: unresolved states and pending messages never pruned; latest two completed checkpoints per role plus seven days of terminal receipts, disk cap refuses new swaps before exhaustion. Bridge history is not deleted.

Core adapter contract stays the spec's method names: observe, safe_point, request_checkpoint, validate_checkpoint, park_old, launch_candidate, candidate_ready, activate_exact, inbox_ack, retire_old, abort_candidate, restore_old, page. Host effects bind handover ID, coordinator incarnation, exact old identity and deadline, with lookup/reconciliation before retries. Typed busy is deferred, never re-executed blindly. Office stop/prove and lifecycle flock remain Beta-owned.

Not proven by offline build: trusted live hooks, unattended app launcher, per-thread process attribution in a shared app server, same-UID malicious peer isolation, SDK semantics or a real session/seat swap. Capability failures keep the adapter manual and cannot be waived by a mock test.

## Host adapter handoff

The common library is not a launcher. Beta supplies Office effects under its lifecycle lock; real crew adapters remain manual until their probes pass. Every effect packet contains handover_id, owner_token, stable effect_id, deadline, exact descriptor, checkpoint/candidate metadata and journal_path. The adapter must atomically validate the owner at its own effect boundary (owns_effect alone is not that atomic fence). lookup uses the same stable effect ID, including after owner adoption. pending never means safe to start another effect. busy requires no_effect=True; whole-wake lifecycle contention is a normal deferral.

Launch receipts must have fresh session_id and incarnation, both different from the old descriptor. Readiness binds that candidate incarnation and the exact host_id, epoch_id, generation, model and sdk_version, plus note_hash, permissions_hash, watermark and verified bootstrap_fill_pct below warn_pct. Host-normalize the trusted roster incarnation to a canonical string. The note is quoted data. Unknown SDK/fill/permissions/account/process evidence cannot be upgraded by an Office assertion.

Host safe_point receipts may supply business_disabled_at, and inbox_ack/restore_old may supply business_enabled_at from the same verified clock. Missing stamps remain null; unavailable_s is computed only from both host stamps. parked_s separately measures coordinator park-to-ACK/restore transitions and is not decision-unavailable proof. Trigger/activated/restored/terminal fields are always present, numeric or null. Recovery/page transport failures stay visible. No model turn, brain query, full transcript scan or wait is installed in a hook by this library.
