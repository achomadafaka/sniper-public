# Office v2 UI implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline; Zeta reviews the final branch.

**Goal:** Show host-published seat work and send authenticated operator DMs.
**Architecture:** Reuse the Office page, bounded SQLite readers and text-only DOM creation. Beta owns producers, schema, retention and operator_dm; Epsilon owns projection, HTTP and UI. No seat filesystem access.
**Tech Stack:** Python/Flask, SQLite, browser JavaScript; no new dependencies.
**Spec:** beta/office-v2-spec:docs/superpowers/specs/2026-10-30-office-v2-persistent-seats-design.md

## Global constraints
- No money, .env, runtime or shared-checkout changes. Own branch in approved worktree.
- Events and mail have separate cursors; default bounded latest tail, indexed reads only.
- Text and refs at most 4096 UTF-8 bytes; unavailable and empty differ.
- Current epoch, generation and incarnation come from host roster. Never infer current identity from an event.
- DM sender is host-assigned operator; explicit dashboard auth, same-origin JSON, stable client_id across retries.
- Display only emitted thoughts; hostile content is text, never HTML or a navigable URL.
- Beta owns 14-day event retention. UI adds no persistent writer.

## Review focus
- Stale or future events must not appear as current seat work.
- Missing sources, unknown clocks and truncated windows remain labelled.
- XSS payloads remain literal text in all feed and workspace fields.
- Auth disabled globally must never open the new DM endpoint.
- Lost DM response must permit an idempotent retry without duplicating mail.
