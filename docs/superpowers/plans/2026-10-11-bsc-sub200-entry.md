# BSC entry preparation and honest sub-200 ms measurement — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans when implementing this plan.

**Status:** operator-approved implementation plan, 2026-10-11. Implementation and gated activation authorized; higher RPC cadence and manufactured funded tests remain outside scope. [Review result](../../audits/2026-10-11-bsc-entry-speed/design-review.md).

**Goal:** remove known BSC preparation waits, target native warm dispatch within 40 ms of original ingress, and measure actual successful receipt observations against the requested 200 ms goal.

**Architecture:** extend existing clock/trace propagation and native candidate safety warming; reuse native snapshot/sizing and full shared quote-envelope seams. Preserve live state checks, wallet locking, durable submission and receipt accounting. Measure head/receipt delivery independently, off-path.

**Tech stack:** existing Python/threading, authenticated Unix datagram IPC, EVM RPC clients, SQLite timing DB and pytest; no new dependency or trading service.

**Contract:** [design](../specs/2026-10-11-bsc-sub200-entry-design.md). [Frozen evidence](../../audits/2026-10-11-bsc-entry-speed/baseline.md).

## Global constraints and review focus

- Before each money-path edit, publish its edge cases and exclusions from design §8 to the operator. No new synchronous read, wait, retry or lock on entry; measure trace/cache lookup p50/p90.
- Inspect current code and current docs again at implementation start. Work from merged main in an isolated `codex/` worktree; leave other chats' Solana work and dirty main files alone.
- Existing proof, round-trip safety, final clip, signed floors, source age, exposure/loss controls, flock lifetime, nonce generation and unsigned-only fallback remain authoritative.
- Preserve configured 1.1 s background safety pacing and nine-second snapshot cadence. A new thread/client must share the account budget; no silent rate increase or entry join on a warm Future.
- One job per commit. Tests first: show the intended regression fails, then implement and run its focused suite with `-n 2`. Full validation uses `flock /home/bigpapi/.cache/codex-pytest-full.lock python3 -m pytest -n 2 ...` once, if required. No provider stress, service changes or funded replay for testing.
- Exact venue/state/clip/custody binding and original T0 are the review priorities. Do not confuse prepared quotes with shared safety PASS, ACK with execution, lock-held time with acquisition, or historical successes with current-release evidence.
- No new cross-lane native work queue/async settlement. The existing two-second handoff hint and flock require a separately reviewed ownership design before concurrency can change.
