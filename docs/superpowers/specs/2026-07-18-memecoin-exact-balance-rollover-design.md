# Memecoin Exact-Balance Rollover Design

**Date:** 2026-07-18
**Status:** Approved for funded implementation

## Goal

Make the funded rollover engine act on the price obtainable for the remaining full position, preserve the four pre-cutover bags' existing exit policy, and activate the corrected policy for new real entries without a paper-data waiting gate.

## Funded Policy Contract

Positions opened before `MEMECOIN_REAL_ROLLOVER_MIN_OPENED_AT` keep the legacy defaults:

- full take-profit at `MEMECOIN_REAL_LEGACY_TP_PCT=60`;
- de-risk disabled;
- default trail disabled;
- catastrophe, mirror, max-hold, manual targets, and explicit position overrides unchanged.

Positions opened at or after the cutoff use:

- `MEMECOIN_REAL_TP_PCT=0`;
- `MEMECOIN_REAL_DERISK_PCT=40`;
- `MEMECOIN_REAL_TRAIL_PCT=30`;
- `MEMECOIN_REAL_TRAIL_ARM_PCT=15`.

The cutoff selects the complete default TP/de-risk/trail policy. It must never gate only the trail. Any explicit per-position override remains authoritative for the fields it sets, regardless of whether it was written by the operator or an entry-time system policy.

The cutoff must be an offset-aware ISO timestamp. Comparisons normalize both values to UTC. An armed rollover configuration with a missing, naive, or unparseable cutoff fails startup validation.

## Executable Price and Peak

`peak_price` remains the nominal/display high-water used by existing UI and historical surfaces. The funded trail receives a separate persisted `executable_peak_price` so an unsellable display spike cannot arm or move the trail.

For every position with an active default or explicit trail, every exit sweep obtains the venue's exact-balance sell preview. The executable unit price is:

```text
expected full-balance proceeds / remaining open quantity
```

It is never divided by original entry notional. This stays correct after a partial de-risk.

The executable quote drives all rollover decisions for the new cohort:

- de-risk threshold nomination;
- executable peak advancement and trail arming;
- giveback nomination;
- final executable confirmation and audit detail.

Priced Solana/EVM and blind 4663 positions use the same helper and the same stored executable peak. Display prices remain available for market-cap targets and operator display surfaces, but cannot establish a funded trail high-water.

**Supersession, 2026-10-19:** the display-price allowance above no longer applies to custom TP/SL cap targets or legacy full-sell cap bands. Their confirmation uses the exact unit sell value (`expected quote proceeds / quoted quantity`) multiplied by the existing position target supply; TP additionally requires a sufficient signed minimum output. SL remains a trigger and may fill below its cap. See the [dated exit-control amendment](2026-07-14-memecoin-per-position-exit-control-design.md#2026-10-19-amendment-exact-saves-and-executable-cap-targets). Other rollover/default rails and chart display remain unchanged.

If an exact preview or remaining quantity is unavailable, the executable peak does not advance and no rollover price exit is submitted. Existing fail-closed confirmation behavior remains.

## Audit Contract

Every nominated executable reason writes `memecoin_exit_trigger_audit` on every venue. A stop or catastrophe waiting for debounce writes an `allowed=0` row with `code=debounce_pending`, current hit count, and required hit count. It does not submit an exit before confirmation count is met.

## Deployment Contract

`scripts/deploy_memecoin_runtime.sh` gains an explicit rollover-activation path. It runs release tests first, then performs one bounded cutover:

1. verify zero pending reservations before validation;
2. stop the pinned old runner so no position can open after the anchor;
3. recheck zero pending reservations after the stop, closing the validation-window race;
4. back up `.env` and atomically write TP, de-risk, trail, arm, legacy TP, and a cutoff generated by `real_utc_now_iso()` from the state clock;
5. validate the funded configuration with the exact release;
6. switch the pinned runtime and start the new runner;
7. verify PID, release path, heartbeat, and loaded policy;
8. on any failure, restore `.env`, the old runtime, and the old process.

This path does not wait for paper evidence. It only enforces execution, configuration, reservation, backup, and rollback safety.

## Tests

Required red-green regressions:

- pre-cutoff positions retain legacy TP/de-risk/trail while post-cutoff positions use rollover defaults;
- offset-aware timestamps compare by instant, and naive/missing armed cutoffs fail validation;
- 4663 `derisk -> executable 3x peak -> executable 2x` exits at the 30% giveback;
- a priced venue with display peak `2.0` but executable peak `1.3` never stores `2.0` as the executable peak;
- priced and blind venues share exact-price nomination, confirmation, and audit behavior;
- first debounced stop/catastrophe sweep writes `debounce_pending` audit;
- deploy activation writes the corrected-clock cutoff and restores config/runtime on injected failure.

The full deployment-selected memecoin suite, `pytest -k memecoin`, schema validation, compile validation, and `git diff --check` must pass before merge.

## Non-Goals

- No paper-only promotion or evidence waiting period.
- No predictive ML crash classifier in this change; the funded signal is executable high-water giveback.
- No changes to entry selection, wallet approval, sizing, or candidate research gates.
- No automatic action on the four pre-cutover bags beyond their existing funded rails and explicit overrides.
