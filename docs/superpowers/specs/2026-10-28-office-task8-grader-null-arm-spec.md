# Office Task 8 spec: opportunity capture, deterministic grader, null arm, auditor (Gamma, for Epsilon)

Binds `docs/audits/2026-10-28-office-readiness-preregistration.md` (Amendments 1-3). Owner of code: Epsilon. Reviewer: Zeta. Spec owner: Gamma. Files: `sniper/office/{auditor,grader,null_arm,capture}.py`, `scripts/office_auditor.py`, `config/office/metric_registry.json`, `config/office/l_null.json`, tests under `tests/office/`. Nothing here may import a funded module or write outside the Office stores.

## 1. Opportunity capture (`capture.py`)
- Deterministic code (no agent, no LLM) writes **one insert-only `opportunity_log` row per eligible coin per epoch before any agent can read that candidate**. Key `(epoch_id, network_id, mint)`, UNIQUE. Fields: `first_eligible_at` (corrected-UTC float), `shift_id`, `sheet_hash`, `snapshot_hash`, receipt/slot/knowledge cuts, clock sample, `hard_filter_version`, `eligible` (bool) and `reason`.
- Eligible = validated sheet at the decision clock AND passes the Office book's frozen hard filter. A coin appears once per epoch, at its first eligible time.
- **Gaps**: `opportunity_gaps(epoch_id, source, from_at, to_at, state)` with `state` in `observed|degraded|unknown|off`. Any stretch where an eligible-universe source is `unknown` or `off` is a gap row. A dead source is a gap, never "no candidates".
- The agent-facing tool refuses a candidate that has no log row (`not_in_opportunity_log`).

## 2. Grader (`grader.py`) and metric registry
- **Driven from the opportunity log, not from decisions**: `grade_epoch(epoch_id)` iterates `opportunity_log` and joins an optional decision and an optional fill. `grade(epoch_id, network_id, mint) -> Grade` is the per-coin form. A handover-window or unprocessed opportunity has **no decision**; it is still graded and `N` is preserved. Deterministic: same inputs, byte-identical output.
- Per eligible coin it yields `{coin_id (network_id:mint), day (UTC date of first_eligible_at), shift_id, decision_id|null, entered, y, y_censored, partial}`:
  - `entered` true: `y` = real Office-book net P&L in USD at the fixed clip, after the execution-cost bound `B` on every fill and exit (single debit). `y_censored` true when the outcome is unknown at the look (no sell route, stale mark > 60 s, unfilled liquidity); then `y` is null, never 0.
  - `entered` false and `y = 0` **only when no actual cash flow is proved** for the coin. **Missing entry telemetry is censored, not SKIP.** A partial fill is scored at actual quantity and cash flows and flagged `partial`.
  - SKIP, veto and uncovered coins also get a descriptive counterfactual from the null arm's outcome for that coin.
- **Store**: `grades` and `outcome_captures` live in the Task 1 **private evaluation store** (`data/office/evaluation.db`), not in the supervisor's `office.db`. The grader, auditor and export hold their own authority; the Head and Quant have **no raw outcome visibility** until the preregistered look. Insert-only, hash-chained.
- `config/office/metric_registry.json` is crew-owned, frozen with the epoch (hash stored in the epoch row), not writable by the Office process. It holds: clip, `B` reference and evidence id, `L = clip + B_entry + B_exit + max network/rent` components, mark max age 60 s, horizon, censoring rules, price-list snapshot id.
- Fired agents stay in every aggregate.

## 3. Null arm (`null_arm.py`)
- `run(opportunities, policy) -> rows` in its **own ledger** `data/office/null_ledger.db` (a separate file from the Office ledger; no shared rows).
- **Primary null** (prereg Am1/Am3): enter **every** eligible coin at `first_eligible_at + L_null(shift_id)`; same fixed clip, same fill model, same `B`, same capacity (max concurrent, daily loss, order of arrival), and the exit policy pinned at the epoch's start version. `L_null` is the per-shift median decision-to-fill latency in `config/office/l_null.json`, measured in discovery or the prior epoch, **frozen before the epoch** with its evidence.
- **Diagnostics, never exported to the verdict**: the same rule at zero added delay; a random subset of the Office's entry count (fixed seed).
- **Clocks**: `first_eligible_at`, `L_null` and the ledger's `now`, due and fill times are all **corrected UTC** (Beta's ledger, `6f82914e6`). Only the arguments to `ps_paper.buy/sell` are converted to host time (+offset), exactly once. Convert at the quote boundary with an **immutable, referenced clock sample** (a stored `clock_sample_id` valid for that scheduled quote: host cut, corrected cut, offset, max age 3600 s as in the ledger), not one offset number held for the epoch. **Persist the sample id and both cuts** with the quote. A stale or unknown sample refuses the quote (`clock_unknown`, censored); old records are never reinterpreted with a later offset. `L_null` names the actual **eligible -> fill** interval measured per shift; `ledger.submit` already adds `ENTRY_DELAY_S`, so the null submits at `first_eligible_at + L_null - ENTRY_DELAY_S` and never counts that delay twice. **Validation**: `L_null >= ENTRY_DELAY_S` for every shift, else that shift is `infeasible` and the epoch gets no verdict; a submit target never precedes the candidate's eligibility. The zero-added-delay diagnostic still pays the mechanical `ENTRY_DELAY_S` and never backdates a request.
- Per coin it returns `n`, `n_censored`. A null outcome is censored when unknown at the look.

## 4. Export for the verdict (`export_epoch(epoch_id) -> dict`)
A **verified envelope**, not loose booleans: `{coins: [{id, day, y, n, entered, y_censored, n_censored, shift_id}], params: {k, delta0, delta1, clip, loss_bound, n_upper|null}, proofs: {...}}`. `proofs` carries identifiers my adapter checks against files and stores: `metric_registry_hash`, `calibration_proof_id` (my commit of the calibration plan, code and result for this k), `n_plan` and the stopping rule, `block_days`, `alpha_support` (the k values the calibration supports), `cost_rule_id` (flat 800 USD per month rule, Amendment 4; `cost` = `flat_office_cost(epoch days)`), `exec_bound_evidence_id`, `gaps`. Diagnostics are not included. My adapter checks that every proof is present and consistent with the epoch parameters (ids, `k` in `alpha_support`, `block_days`, `n_plan`); it does **not** open the evidence. The **exporter must itself resolve each evidence reference and hash** (registry file hash, calibration proof file, cost rule file, execution-bound evidence) and refuse to emit an envelope with an unresolved or mismatching one; the auditor spot-checks the resolution. **No positive verdict from an unvalidated fixture.**

## 5. Auditor (`auditor.py`, `scripts/office_auditor.py`), its own unit
- `verify_chain` on every append-only table, plus a **head pin**:
  - The pin is `(head_seq, head_row_hash)` per table, stored by the auditor outside any path the supervisor can write (`data/office/auditor/pins.json`, atomic temp-write, fsync, rename).
  - The auditor advances the pin only after `verify_chain` from the old pin to the current head succeeds, so a **legitimate append is not a false alarm**.
  - A table whose current `seq` is below the pin, or whose hash at the pin `seq` differs, is a **deleted tail** and pages.
  - At first start with **no trusted pin the state is `unknown` and pages**; it is never treated as clean.
- Zero-tolerance counters (prereg 9 plus Am3): unauthorized funded writes; accepted future-knowledge reads; altered or deleted decision or evidence identities; duplicate credited fills; ledger reconciliation errors; scorer changes inside a frozen window; unlabelled model fallbacks; **replay ran while live work was backlogged**.
- Reconciliation: settled cash = initial + net external flows + sell proceeds - buy spend - costs, per book and for the evaluated epoch. External flows come from the ledger as it exists (`capital_flows` by kind `initial|deposit|withdrawal`; `ledger.external_flows(conn, book_id=None)` at `6f82914e6`), never from a table invented here; transfers net to zero by kind and are checked against the epoch's frozen rule; equity = settled cash + conservative liquidation value.
- Pages through `memecoin_alerts.send_alert(kind="office-audit", ...)` on any breach or when the supervisor or Head is dead. The auditor and its channel sit outside the editable org.

## 7. Proof artifact schemas (what the exporter resolves; added rev 5)
Every artifact is a JSON file under the approved proof root (`config/office/proofs/`), referenced by id and by file hash. The exporter opens each, recomputes its hash, and refuses to emit when anything is missing, unknown or mismatching. **The exporter invents none of these values.** Until an artifact exists the field is the explicit token `"unmeasured"` and the export is refused.
- **Calibration proof** (`office-calibration-proof-v1`, produced by `sniper.office.readiness.calibration.make_proof`, code on branch `gamma/office-verdict`): `{schema, k, params{n_coins, days, block_days, alpha_scale, day_method, delta0, delta1, sigma, draws}, code_commit, plan_sha256, created_at, generators[{name, method, reps, supported, power_claim, type1_upper, power_lower, reason}], supported_for_k, power_claim_for_k, proof_id}`. `proof_id` = sha256 of the canonical JSON of everything else. The exporter requires `supported_for_k` true for the epoch's `k`, and `params.block_days`, `params.alpha_scale`, `n_plan` equal to the epoch's.
- **Cost**: flat 800 USD per month by operator order; `config/office/cost_allocation_rule.json` (`office-cost-allocation-v2`), `C = sum over the epoch's UTC days of 800 / days_in_month`. No fee attestations, cost proofs, usage weights or shadow prices exist. Usage may be logged for ops and never enters cost.
- **Execution-bound evidence**: `{id, venue, clip_band, latency_regime, bound_usd_per_fill, method, sample_n, source_refs[], created_at}`; independent of the Office and matched to the epoch's venue, band and latency regime.
- **Metric registry**: the economics fields (clip, `B` reference, `L` components, mark max age, horizon, `n_upper` rule) are `"unmeasured"` until the operator or crew freezes them; Lambda's Brier-only fields stay descriptive and do not satisfy the economics fields.
- **`L_null`** (`config/office/l_null.json`): `{epoch_id, shifts[{shift_id, utc_hours, l_null_s, sample_n, evidence_ref}]}`; `l_null_s >= ENTRY_DELAY_S` per shift.

## 8. Rev 7 (Gamma, from Zeta's T8 source HOLD on `ee44508e2`): coverage and read-cut contracts
1. **Coverage is proven, never inferred from an empty gap table.** For every expected eligible-universe source the capture writes insert-only `opportunity_coverage(epoch_id, source, from_at, to_at, state, proof)` rows with `state = observed`, only for intervals where a successful eligible poll or capture proof exists. The export requires the `observed` intervals of **every expected source** to cover the **whole epoch** `[opened_at, look_at]`; any uncovered stretch is `unknown` and either censors the coins/time it touches by the rule in prereg Amendment 2 or refuses the export. An empty `opportunity_gaps` table means nothing. A slot/time-range check by heuristic (first/last received +/- a margin) is not coverage: use the proven minimum and maximum bound of the captured rows, or an exact bounded received window, so an interior outlier cannot be missed.
2. **One immutable read cut.** Two store files cannot be read atomically, so the export takes a **cut**: for every append-only table it records `(head_seq, head_row_hash)` first, the auditor verifies those heads, and the export then consumes **only rows with `seq <= head_seq` per table** (and pins the opportunity, grade and execution reads to the same cut). Rows appended after the cut are invisible to this export. A caller's open transaction is preserved. The cut (all heads) is part of the verified envelope and stored with the verdict.
3. **Test witnesses owed**: (a) an interior swap outlier between two valid captured rows is not hidden by coverage; (b) an export with empty gaps and no coverage rows refuses; (c) a writer appending an opportunity and a grade between the auditor's head check and the export's SELECT changes neither the exported coin set nor the audited count (the export equals the cut).

## 9. Rev 8 (Gamma, for Epsilon's T8 strict consumer): the `equity_snapshot` reference
`ledger.equity(now=look)` reads the CURRENT order, cashflow and mark state, so a live ledger handle used for a historical cut is look-ahead. The epoch manifest therefore carries an `equity_snapshot` ref: `{path, sha256}` rooted at the approved config root (same resolver rules as the nominee refs), pointing to an immutable copy of the evaluated Office ledger plus a metadata sidecar. Frozen fields of the sidecar `office-equity-snapshot-v1`:
- `epoch_id`; `as_of_cut` (corrected-UTC float, must equal the epoch `look_at`); `taken_at` (corrected UTC, must be `>= as_of_cut`); `clock_sample_id`, `clock_offset_s`, `clock_sampled_at_host` (the one sample used).
- `ledger`: `{sha256, user_version, books: [evaluated book ids], order_count, mark_count, cashflow_count, max_order_time, max_cashflow_at, max_mark_at}` computed over the copy.
- `fx`: `{sol_usd, sol_usd_at (corrected), source, source_ref, max_age_s}` with `sol_usd_at <= as_of_cut` and `as_of_cut - sol_usd_at <= max_age_s` (the ledger's 120 s rule); no FX = the snapshot is unusable.
- `receipt`: `{id, metadata_sha256, written_by, written_by_identity}` where `written_by_identity` is the trusted snapshotter identity the launcher pins; a file hash alone proves consistency, not historical authenticity (T15 supplies the authenticated as-of capture).
Exporter rules:
1. Resolve and hash the snapshot from the approved root, open it **read-only and immutable** (`mode=ro&immutable=1`); no live API and no fallback to the current mutable ledger. Missing, unreadable or unauthenticated = refuse.
2. **No look-ahead check**: scanning the copy, every order, fill, exit, cashflow and mark time must be `<= as_of_cut`; any later row means the copy was taken after the cut with later activity and is refused (the copy is taken AT the cut, not trimmed afterwards). Counts and max times must equal the sidecar.
3. Call `equity(epoch_id=..., kind='evaluated', require_proven=True)` on that handle; `partial` or `unknown` = the verdict is refused with an unknown summary (never a partial figure). Seal `cash`, `known_liq_lower`, the unpriced count and quantity, and `binding_kind_counts` from that **same** result in the envelope.
4. The snapshot hash and the sidecar hash enter the verified envelope and the nominee `proofs`.
5. Tests: a snapshot with a later cashflow is refused; a stale or missing FX is refused; a changed byte is refused; a live-ledger handle is refused; a partial equity refuses the verdict; the sealed figures all come from one `equity()` call.
