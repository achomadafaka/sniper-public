# Desk decision quality: pre-registration (frozen 2026-10-23, Gamma)

Three recording-only pieces (operator order via Alpha: make desk decisions better and faster; builds wait for the operator's pick). Measurement only. No live change, no cohort change, no funded authority, no copy advice. Edits after the first read are amendments at the bottom.

## Part 1: PASS-pool label table (offline, read-only)
Source: `data/memecoin_desk.db` desk_tickets stage='hard_filter' verdict='PASS' (one row per opportunity; ~300/day, not 1,100: the 1,100/day figure was raw emissions), candidate features from desk_candidate_emissions.candidate_json (snapshot fields), JUDGE verdict from stage='vet'. Outcome source: universe tape `data/desk/swaps/<utc-date>.db`, curve spot = (virtual_quote/1e9)/(virtual_token/1e6) per swap. Days: 2026-10-22 and 2026-10-23 (tape from 10-21 exists but hard-filter PASS rows start 10-22).
Unit: one PASS ticket. Entry reference E0 = last tape spot at/before PASS ts; E8 = last tape spot at/before PASS ts + 8 s (primary: the achievable entry at today's latency). Labels from E8: ret@60/180/300 s, max run %, max drawdown %, rail outcome under 30/18/12 (tp/sl/trail; trail armed after the first tick above entry; exits on curve spot, no impact/fees; the vet verdict's own rails when present, else 30/18/12). Right-censoring: a ticket whose tape has no swap after PASS+300 s is censored and counted, never labelled. A coin that graduates (real_quote ~85 SOL, curve swaps stop) is labelled `graduated` and its last curve spot is used for all later horizons: a lower bound of its outcome, reported separately.
Reads (the only ones):
- R1 base rate of the pool: mean, median, win% of rail return; ret@300; 95% bootstrap CI (2,000 resamples, seed 23); by policy_hash (hard-filter policy changed 10-22 ~11:00Z) and by day.
- R2 JUDGE versus the pool: ENTER vs SKIP vs not-called, mean rail return with bootstrap CIs and the ENTER-minus-SKIP difference with CI. n is small (ENTER ~10/day): report n first and write "no detectable difference" when the CI spans 0.
- R3 features: univariate quantile tables (terciles) for curve_pct, mcap_usd, liq_usd, flow_60s buy_n/sell_n/makers/largest_buy, buy/sell usd ratio, price_vs_60s_high_pct, price_vs_60s_low_pct, hard-filter top10_pct, creator_pct, round_trip_loss_pct. All features reported, none cherry-picked; a feature is "replicating" only if its top-vs-bottom tercile sign matches on both days. Missing values (completeness != complete) are their own bucket, never zero.
- Gates: G1 tape coverage (share of tickets censored; if >25% the table is labelled partial). G2 no model fit until >=300 labelled tickets; until then R3 is descriptive.
Forbidden conclusions: no 'use feature X as a filter', no EV claim, no sizing from this table. It informs which JUDGE/ranker experiment to pre-register next.

## Part 2: thinking-on vs thinking-off shadow A/B (draft, to freeze before the first shadow row)
Design: for each live JUDGE ticket, Beta's shadow call runs the same rendered sheet with thinking disabled and records verdict, rails, input hash, wall and duration_api_ms. No action ever follows the shadow verdict. Per ticket store: ticket_id, sheet hash, verdict_on, verdict_off, rails both, tokens, timings.
Reads: (a) 2x2 agreement matrix on ENTER/SKIP; (b) latency delta (wall) paired; (c) on the DISAGREEMENT set only, tape-forward rail return (Part 1 labels) of the coin that on-ENTER/off-SKIP and off-ENTER/on-SKIP would have traded, mean difference with bootstrap CI.
Promotion rule (to a NEW cohort, never in place): >=3 days AND ENTER agreement >=85% AND mean rail return (off minus on) on the disagreement set >= -3pp (CI lower bound reported) AND shadow did not slow the live call. This is a no-harm check: ~10 ENTER/day cannot prove improvement. Stop: shadow adds >0.5 s to the live path or hits the shared login caps.

## Part 3: cap-refusal log (spec, recording only)
Every `desk verdict price` refusal records: ticket_id, mint, verdict price + snapshot age, exact quote price + its unit, quote observed_at, tape spot at verdict time and at quote time, elapsed verdict->quote, cap, gap % vs verdict and vs spot-at-quote, impact+fee component if the quote exposes it. Purpose: separate staleness/momentum from impact/fee in the 4.6% cap and grade refused entries from the QUOTE price. Rule to widen the cap (future, not now): refused set mean rail return from quote price >= accepted set mean - 3pp on >=30 refusals. Unit trap: quote_price in memecoin_entry_attempts is ~100x the tape spot scale; compare ratios only.
