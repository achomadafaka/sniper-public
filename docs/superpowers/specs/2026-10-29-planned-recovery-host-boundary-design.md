# Planned recovery: isolated host adapter, signer and canary proof

Status: DESIGN REVIEW REQUIRED. No host installation, key creation, service change or activation. Delta owns this design; Zeta reviews. Alpha takes final exact sudo commands to the operator. This extends approved offline protocol 08ef497f4 plus provisioning hardening bdb57b955, not its live authority.

## Smallest host boundary

Prefer an **operator-invoked, root-owned recovery command**, not a signing daemon, user-bus service or new Office-callable endpoint. Root-only invocation handles arm/completion/consume. An isolated root-owned host guardian must own authoritative normal trip/900-second publication too; the present same-UID user watchdog cannot remain an authority writer. Preserve its policy, not its writable path. Automatic fast recovery is deferred: no user-facing protected-consume endpoint is added. The approved five-second shortcut works as an explicit operator recovery ceremony. This is a proposed activation shape, not a claim the operator already approved manual-only operation.

The root recovery command is not a general signer or JSON-signing API. It constructs every signed field from a fixed root policy and independent host reads; only kind and a full target SHA may be requested. It never accepts caller-supplied healthy=true, process identity, arbitrary paths, bytes to sign, command argv or a claim that containment succeeded. No funded entry, exit, sizing, custody, RPC, signing or order operations are implemented by this helper. It may only publish the approved Office guard recovery latch.

## Operation and concurrency

Root adapter takes one nonblocking root lock for state transition/consume, not across the five-second observation interval. It reopens and validates immutable state identity after reacquiring; another operation/nonce/boot change aborts. Exact JSON schema, nonfinite/bool rejection, fixed4KiB records, monotonic boottime deadline and one active operation are retained. Root-owned state corruption/loss does not auto-initialize or reset the watermark. Initial installation initializes once BEFORE any operation can arm. Reboot requires explicit root reinitialization for the new boot and retires old authority; no same-boot reset command.

**Arm:** in an operator-owned root session, immediately before the planned stop and after the existing validation/drains, independently prove current ready guard freshness, ordinary healthy host conditions, authenticated funded heartbeat, exact old process/release, exact target pin and approved stop/deploy driver identity. Construct and publish the300s record. Bind the still-live operator stop-controller PID/start ticks and fixed action identity, not the short-lived signer PID. Root parent identity is independently probed, never an arbitrary --issuer-pid option. Record private state before exposing public authority. Signer exit closes all key descriptors. No synchronous guard acknowledgement is required; missed acceptance loses only the shortcut.

**Stop/cutover:** Alpha/operator runs the existing stop, lease-expiry, dry-run, review, apply and restart contracts. Signing authority is not stop authority. Planned Office stop must include proof of actual stopped service processes; funded code deploy must preserve all existing validation, entry/exit drains, reconciliation, provider readiness and rollback gates. This helper never stops/restarts funded services or changes .env.

**Complete:** operator root command verifies successful target identity independently, original nonce/deadline unchanged, controller alive, ordinary current health and absence of deployment intent/owned entry hold as relevant. For Office stops the completion can precede supervisor start: expected target release/config pins, stopped supervisor/launcher, expired lease and independent root-safe repin validation are necessary. Success JSON or a user-writable helper, release script, Git hook, SQLite extension or import is never privileged evidence. The immutable root validator independently checks bounded regular bytes against root-approved manifest pins, config contents and link identity, service PID/control state, and read-only lease/epoch/roster/capital witnesses. Use an isolated root-owned OS interpreter/stdlib, SQLite extension loading disabled and trusted_schema off; never execute candidate release or checkout code as root. Approved user dry-run output is diagnostic corroboration only. If the root validator cannot establish a field independently, refuse completion. Do not falsely claim a new supervisor process exists before restart. The offline schema currently requires a result process; a reviewed schema revision must distinguish `office_restart_prepared` (validated release + stopped/expired-lease witness) from `funded_target_healthy` (actual live funded PID/birth/release). Reusing the funded process field for Office is prohibited. Rollback eligibility remains excluded.

**Recover:** root command verifies signature and private accepted context, then gathers at least five seconds of fresh ordinary health with two advancing authenticated funded-heartbeat timestamps from the same verified funded process. No funded read RPC. Recheck guard authority, intent, release, containment, boot and deadline after observation. The old user watchdog must be retired as an authority writer by a separately approved migration before activation; stopping it alone is not writer exclusion. The new host guardian and root operator pause/recover commands must all use the same root-owned lock and monotonic guard revision. This is not permission to change services now. Unknown guardian identity, a legacy writer still configured, failed containment, or changed revision refuses recovery. Other Office stop prerequisites and original discovery epoch remain in force.

Persist consumption and fsync it BEFORE publishing ready. The authoritative destination is ONLY `/var/lib/sniper-office-guard/guard.json`, under root-owned non-user-writable ancestors; never the current user-owned `data/office-control/guard` tree or a symlink beneath it. Anchor the protected destination with held no-follow directory FDs and bounded reads; temp creation/rename use that directory FD. Reacquire the common root lock after the five-second observation, compare the saved root guard revision and bytes, revalidate health/authority, durably consume, and publish ready/revision+1 while STILL holding the lock. This is writer exclusion plus atomic replacement, NOT filesystem CAS: recheck+rename alone would be insufficient. Every legitimate writer (normal guardian pause/refresh, operator pause, recovery, initialization and rollback) MUST take this same lock; an arbitrary root process bypassing it is outside the root-compromise boundary. Non-root writers are excluded by ownership and all ancestors, not by goodwill or stopping one daemon. The public-verifier guardian keeps real healthy_since/recovery_basis/provenance and ordinary900s eligibility truthful; only the root operator command may consume. Any later failure uses normal policy; consumed authority cannot be used again.

Crash before durable consume: no ready publication. Crash after consume/before ready: shortcut lost, ordinary recovery. Crash after ready/before watchdog starts: ready becomes stale; consumed record cannot rescue it. No file deletion/rewrite of an operator pause, unknown/malformed latch or unrelated fault. Do not retry consume by restoring old state; operator follows normal recovery.

## Office stale-latch attribution

Only exact root-signed pre-stop ready bytes can explain a ready latch aging during a planned Office stop. A previously paused latch, a new paused guard_stale written during a failed restart, different at/hash/version, missing latch or fabricated readiness cannot be reclassified. Signer must bind both pre-stop host timestamp and boottime and actual pre-stop freshness. The adapter cannot infer historical authority from today's registry or matching text alone.

Root publication is a prerequisite, not a transparent path substitution. The reviewed migration must update every supervisor/launcher/model/VM/floor/monitor/installer/preflight guard-path consumer and approved config/hash, add a root-owned minimal guardian artifact/unit with an independently validated import graph, then retire the old writer. No automatic fallback to a user-writable guard path. The root guardian has no signing command/network, no key/state handles inherited, private-key directory masked, non-dumpable/capability restriction and canary proof; it may write only protected guard/private state and the exact delegated Office cgroup kill file. It reads host observations directly through root-safe code, not caller-supplied health JSON as authority. This root guardian is a new activation design requiring Alpha approval and Zeta review, not implemented or installed.

Guard stale handling is not globally relaxed. If watchdog already restarted and replaced the old ready bytes with a paused malformed latch, the proposed shortcut refuses; the operator keeps normal recovery. An extension to preserve signed attribution through that restart requires another RED/GREEN adapter rule, not deleting auto_resume_blocked. Correct order is independent root-safe complete validation -> root recover against protected revision while the guardian is stopped or cooperatively serialized -> root guardian fresh publication -> remaining auxiliaries -> supervisor, retaining existing safety checks. An active guardian that refreshes the revision during observation causes a conservative retry/refusal; it may not be ignored. Exact ordering and a live canary are review gates, not actions taken here.

## Funded deploy ceremony remains an explicit design gate

A normal funded gate lasts longer than300s. Arming before the test suite cannot provide a reliable shortcut and must not be advertised as supported. The arm point is after validation/drains immediately before old stop. Operator-run sudo-only authority means an unprivileged deploy script cannot sign automatically or access cached root credentials. No sudoers/polkit rule, user socket, watched user request file or signer RPC is permitted to bridge that gap.

Select the **operator checkpoint only** for v1, not a privileged orchestrator. The operator invokes separate root arm and completion/recover commands at the reviewed stop boundary; each invocation independently authenticates and validates current root-safe evidence. There is no parent that drops UID and later attempts to regain privilege, no privileged child executing the checkout, and no inherited key/state handles or root-capable continuation. Existing deploy code always runs under its existing unprivileged identity. The checkpoint implementation does not exist yet; root must never execute user-writable deploy code. A new checkpoint cannot add any wait/lock/retry on entry/exit execution; measure actual admission-hold overhead separately and keep unplanned/failed/missed signing equivalent to existing deployment. Until that handoff is reviewed, funded deploy remains normal900s recovery. Do not silently call the feature fully wired after only Office integration works.

## Canary proof before private key creation

Build a separate root-owned harmless canary file under the future key directory and protected replay directory. No real key or secret needed. Record exact code/unit/sandbox hashes and uid/gid/kernel metadata. The operator runs the privileged fixture; Delta/Zeta review results. Every expected read/write attempt must fail for each actual supervisor, launcher, Claude child, Codex child and research VM context. A disabled/unstarted VM is untested, not PASS.

Required probes: direct path; path symlink; `/proc/<host-signer-pid>/root/...`; `/proc/<host-signer-pid>/fd/N`; `/proc/<guard-pid>/root/...`; `/proc/self/root/...`; inherited FD enumeration; parent directory traversal; process_vm_readv/ptrace or proc mem with harmless buffer; signer env/cmdline inspection; copying public marker then trying private-state rollback; root helper invocation without root; sudo -n attempts from each Office context (must fail); system/user bus activation attempts (no relevant service); marker/state replacement and symlink race. Do not print any private canary content from a privileged context to an Office context. Use typed permission/identity outcomes and a random public challenge digest.

The signer must set non-dumpable before private-key access, close inherited FDs, avoid key environment/argv, and retain root ownership across helpers. Prove its root UID is not mapped to an Office user-namespace capability. Published marker/public key are readable but not writable; private state and key are neither readable nor writable. Root adapter must have no network and no arbitrary subprocess/shell execution; public OpenSSL calls and fixed process/host reads only. Tests use approved fixture cgroups and fake units, never live funded/Office stops or paid providers.

Offline mandatory adapter witnesses: wrong owner/mode/ancestor; replaced interpreter/module; public-key substitution; symlink/FIFO/oversize path; no-root invocation; stale/forged/replayed/other-boot marker; expired lease unknown; wrong PID birth or multiple candidates; disk-full at each durable boundary; two consume commands; target changed during observation; serialized publication race; crash at every phase; ordinary no-marker behavior unchanged; operator-pause refusal; future/regressed heartbeat; root-state reset refusal; exact ready publication only after consume. Deterministic publication witnesses must suspend recovery after its final check but before rename: (a) a non-root same-UID writer attempts file/ancestor replacement and must receive permission denied; (b) an operator pause taking the shared lock cannot publish inside that critical section, then publishes after recovery and remains the final state; (c) a pause/change committed during the unlocked observation changes revision, so recovery refuses without publishing ready; (d) a kill of recovery after consume leaves no readiness and cannot replay. No test may label check+rename as CAS. Whole-root boundary PASS additionally requires the privileged canary evidence above.

## Operator selection superseding manual-only revision

Alpha's latest operator choice is an **isolated automatic root service**, installed once by the operator, with a retained-root parent and permanently deprivileged child for funded work. This supersedes the manual-only/no-orchestrator selections above; protected root publication, shared writer lock/revision, independent validation and all canary gates remain mandatory. The new root service is the only normal authority publisher. Operator pause commands also take its exact root lock; no user watchdog may write or replace any authoritative ancestor. Recovery observation remains outside that lock; final revalidation/consume/rename is inside. No claim of filesystem CAS.

The parent retains root, but no key descriptor is open across child creation. Child must close inherited descriptors, clear supplementary groups, setgid/setuid permanently, set no_new_privs and use a clean allowlisted environment before executing fixed unprivileged work. Parent never executes candidate code or trusts child success output as completion proof; it independently probes exact target process/boot/birth, root-approved release/config pins, containment, lease and health as relevant. A child exit0 is necessary but not sufficient; crash/partial/unknown completion means no signature/shortcut. The parent cannot accept arbitrary child argv, paths, environment or payload-to-sign from Office.

Root-service trigger/controller and target-approval provenance is still an explicit pre-integration design gate. One-time installation is not authorization for an Office-writable request file or a generic root signing/deployment API. No listener, bus endpoint or sudoers rule may be invented to bypass this issue. The service must either observe an independently authenticated approved host lifecycle or own a fixed-policy child lifecycle whose approved trigger is inaccessible to Office. That ingress must be reviewed, including impersonation/race probes, before the daemon can run it. Source primitives and offline canary fixtures may be built while integration remains inactive. No key or live service exists from this work.
